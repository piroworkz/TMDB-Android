## Summary

Add favorites support for movies and TV shows by extending the existing media catalog data model with `mediaType` and `isFavorite`, exposing favorites use cases, and introducing a new Favorites screen reachable from the navigation drawer. Favorites persist for the current session only, and are cleared by the app when the session ends.

## Implementation Plan

### Phase 0: Repository Research

- Verify current Media catalog flow, Paging setup, and RoomMedia mapping in `MediaCatalogRemoteMediator`.
- Confirm existing Drawer item structure and navigation graph patterns for adding a new destination.
- Confirm test patterns for ViewModel and repository layers (JUnit4 + MockK + Turbine).

### Phase 1: Data and Domain Design

- Extend `RoomMedia` with `mediaType` and `isFavorite` fields; update database and mapping layer.
- Add a `FavoritesDao` with queries for toggling, filtering by media type, and clearing all favorites.
- Extend `Media` with `mediaType` and `isFavorite`; add `Catalog.mediaType` helper.
- Create domain use case interfaces: `ToggleFavorite`, `ObserveFavorites`, `ClearAllFavorites` (use named functions, no `operator invoke`).

### Phase 2: Framework Implementation

- Implement favorites data source and repository wiring in `media_framework`.
- Provide Hilt bindings for new favorites use cases.
- Implement `ClearAllFavorites` to reset all `isFavorite` fields without touching auth modules.

### Phase 3: UI and Navigation

- Add favorite toggle UI on media card composables; bind to `ToggleFavorite` use case.
- Create Favorites screen and ViewModel with Movies/TV tabs and paging lists.
- Add navigation drawer entry and navigation graph route for Favorites.
- Update `MainViewModel.endSession()` to call `ClearAllFavorites` after `CloseSession` success.

### Phase 4: Testing (TDD)

- ViewModel tests for favorites toggling and tab visibility logic.
- DAO tests for favorite queries and clear behavior.
- UI tests for favorite button state and Favorites screen tab/empty-state behavior.
